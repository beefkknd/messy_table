Visual Re-ID study · Part Two · Updated November 12, 2026

Before we can recognise the same object, we have to find it.

We want a system that can look at two photographs and say which objects appear in both. This part asks a simpler question: can it draw a useful box around each object, including the small and partly hidden ones?

Our strongest progress came from teaching YOLO with human-labelled examples, showing it close-up sections of each photo, and preserving more image detail. Feeding its own guesses back into training did not demonstrate the improvement needed to continue that experiment.

1. The problem in everyday terms

Imagine a table covered with cups, packets and boxes, photographed from several directions. We want to recognise the same cup across the photographs. First, the system needs to separate that cup from the objects around it. If it overlooks the cup in either photo, the next stage cannot compare it. If one box contains two objects, the comparison starts with an ambiguous picture.

Detection means finding an object and drawing its box. Identity matching means deciding whether a box in one photograph and a box in another show the same physical object. Finding “a cup” does not establish that it is “the same cup”.

MessyTable provides cluttered scenes, several camera views, and human-drawn boxes with object identities. We use those labels as the answer key to measure how well the detector finds individual everyday objects.

2. What happens to a photograph

We use YOLO26m as the detector: a model that predicts object boxes and gives each a confidence score. We improved what it sees, what it has learned, and how its predictions are combined.

A tile is a close-up cut from the original photo. It gives a small object more space in the detector’s input without inventing detail. Overlap helps avoid losing objects at the cuts. The same object can appear in several tiles, so the combining stage matters.

1024 versus 768 is an input-resolution setting. The whole scene is resized less aggressively at 1024, preserving more detail. In the latest comparison, tile size stays fixed at 768. The tests therefore distinguish larger full-frame inputs from adding tiles.

The useful Step 0 result was mainly about scale. Tiling and higher resolution helped. Earlier work also explored grayscale and local contrast changes, but these are not part of the validated full-test recipe reported here. We have not established that a general “clean up every image” filter improves the system. Colour, printed text and texture can be useful identity evidence.

Training on tiles and predicting on tiles are separate changes. Predicting on tiles reuses an existing model. Training on tiles lets the model learn how objects and clutter look in those close-ups.

3. What the numbers mean

Recall · How much did we find?

If 100 human-labelled objects are present and we find 94, recall is 94%. Missing objects lower recall.

Precision · How trustworthy are the boxes?

If 100 predicted boxes are emitted and 86 can be assigned to different human-labelled objects, precision is 86%. Extra or poorly placed boxes lower precision.

Both-view coverage · Is the object boxed twice?

An object needs a usable box in both photographs. This measures detection in two views; it does not establish the identity.

A usable box must overlap a human reference box sufficiently. The main test uses intersection-over-union, or IoU ≥ 0.50: the shared area must be at least half the total area covered by at least one of the two boxes. Each predicted box and each reference box can count only once.

Unmapped means a prediction cannot be assigned to a distinct labelled object under that rule. It could be a duplicate, a partial object, a box around several objects, background, or scene content outside the dataset’s target list. It does not automatically mean the model imagined an object.

A missed target is different: it is a human-labelled object left without a usable prediction. Unmapped boxes count predictions; missed targets count reference objects. Confusing them can make an apparent improvement look much stronger than it is.

Four lessons from the experiments

  1. Teach the detector what our objects are. The released model finds 38.22% of the reference appearances. The first locally trained model, using 150 fully labelled photos, finds 84.61%. This changes both the weights and the task vocabulary: it learns a single “tabletop item” category from complete scene annotations. The gain is practical adaptation, not proof that data quantity alone caused it.
  2. Close-ups find objects, but they also find misleading fragments. On that first model, raw tiles lift recall to 90.08% while precision falls to 67.04%. A stricter filter removes many extra boxes but also removes real discoveries. A large box count is not success by itself.
  3. Improve the training recipe as well as the data. The 600-photo model was trained at 1024 pixels, with its main feature-extraction layers allowed to learn, smaller learning adjustments later in training, and a mixture of full scenes and tiles. Its raw tile output is much cleaner. Several settings changed relative to the 150-photo run, so we cannot attribute that jump to one setting.
  4. Then separate the two cheap improvements. E → F keeps the 600-photo weights and tiles identical, changing only full-frame inference from 768 to 1024. E → G keeps the training recipe and inference size fixed but expands training from 600 to 2,400 photos. Both help. H combines them and has the strongest coverage in this comparison.

The combined latest result is E → H. Recall rises from 92.45% to 94.01%; both-view coverage rises from 87.73% to 90.12%; unmapped boxes fall from 68,094 to 63,150. This is more useful coverage with fewer extra boxes.

5. What happened to the AlphaGo-inspired idea?

The original idea was to reuse what the model had already found: accept its strongest detections as training labels, train a new version, discover more objects, then repeat. The computer-generated labels are often called pseudo-labels. In this experiment, the “teacher” makes those labels and the “student” is the detector trained with them.

Existing detectorMake confident predictions on more training photos.
→
Automatic labelsAdmit predictions under a fixed quality rule.
→
Student trainingMix these labels with trusted complete scenes.
→
Check for real improvementThe required gain was not achieved. Stop before refreshing the labels.

The analogy suggested a useful experiment, but object detection lacks the clear win/loss feedback of a board game. A detector’s confidence is its own estimate, not an independent answer key. Repeating a prediction does not make it correct. If a real object is omitted from the automatic labels, ordinary training may even teach the student to treat it as background.

The controlled test did not justify another cycle

We compared four short training continuations. They began from the same detector and received the same number of updates. One continued on trusted labels; two used automatic labels; a diagnostic used the complete human labels on the same extra photos. A separate calibration set selected confidence cutoffs to control extra and unmapped output; those cutoffs were then applied to all 100 development pairs. The automatic-label variants improved both-view coverage by only 0.18 and 0.14 percentage points over trusted-label replay. Even complete human labels on those extra photos gained just 0.09 points under that short recipe. None reached the planned three-point gain. Each uncertainty interval includes zero, meaning the data do not establish an improvement over the replay control. The intervals describe variation across setups, not variation across training seeds.

Label quality also weakened at the discovery frontier. In the preselected 240-photo audit, the single-pass automatic labels were 96.97% precise at IoU ≥ 0.50. But the 554 additional labels from the higher-resolution and grayscale passes were only 80.87% precise, dropping to 68.41% with the stricter box-overlap requirement. The labels most likely to expand coverage were less dependable than the familiar ones.

Our decision: park recursive self-labelling. It did not demonstrate a useful coverage gain under the setup we tested, and no successful repeated self-improvement cycle was completed. The later gains in this report come from human-labelled data and a stronger training recipe. They are supervised learning, not an AlphaGo-style result.

This does not show that self-training can never help. The earlier continuation used only 300 extra updates, a constant learning rate, 768-pixel inputs and a largely frozen backbone. Later supervised training changed those conditions and did improve. We have not rerun the automatic-label comparison with that stronger recipe. With thousands of human-labelled training photos still available, automatic label generation has not earned priority here.

6. What we know, and what remains difficult

The detector now provides a much stronger starting point. Human-labelled adaptation was the biggest practical step. Training and predicting at useful scales improved small-object coverage, and more labelled photos improved the result further under the same update budget.

The data are large enough to describe this benchmark, but are not a fresh confirmation test. All official test setups have now been examined during this project. The native training split is excluded from evaluation, but benchmark exposure means these results should not be presented as untouched evidence of generalisation. The same physical products can recur across scene setups.

The latest training comparison has one seed and a fixed compute budget. Its exact counts are valid for these saved runs. We have not established how stable the training gain is across repeated runs, what all 16,920 training photos would achieve, or how long each model needs to reach its best result.

The findings apply to the scenes we tested. MessyTable contains everyday objects arranged on tables. Performance on other environments, object types and lighting conditions needs separate evaluation.

The next practical priorities are clear: preserve the new supervised detector as a reference; understand the remaining small-object and box-quality errors; choose the right precision/recall tradeoff for the intended workflow; and measure how the improved detector changes identity matching (Part Three) on new, representative data. Reopening recursive self-labelling would require a fresh controlled comparison against the stronger supervised recipe.

Fixed scoring rules for technical readers

Detection metrics are pooled, class-agnostic localisation metrics, not category accuracy or threshold-integrated mAP. Predictions use confidence > 0.25. Localisation uses the existing one-to-one maximum eligible IoU-sum assignment at IoU ≥ 0.50; stricter extent recall uses IoU ≥ 0.75. Precision = localised / all predictions; recall = localised / all human appearances. An empty-output photo still contributes all its missed targets.

The latest raw tile merge preserves full-frame boxes, rejects candidates touching an artificial tile boundary within four pixels, maps coordinates back once and deduplicates at IoU 0.55. Tiles are native 768 pixels with stride 576 and edge-aligned final windows. The older D gate additionally applies confidence ≥ 0.80 and geometry checks to tile additions. E–H use the same fixed raw-merge recipe.

Historical self-training results used calibration-selected cutoffs under candidate/unmapped ceilings, then scored Development100. They are not combined with the fixed-cutoff full-test results. The complete-label control changes label completeness and background supervision together, so it does not isolate label noise alone. No repeated teacher refresh qualified.
